# 访问与审批机制

[← README](../README.zh-CN.md)

## 从“需要密码”到“获批使用”

1. ** Agent 发起需求。** `secret-access` Skill 先通过只含元数据的搜索找到资源，再附带使用原因申请读取。
2. ** Plankton 获取调用链。** 进程父子关系、命令参数、脚本引用和请求上下文，帮助判断密码将如何被使用；系统观测与请求方声明保留各自来源。
3. ** 人工或 LLM 审批。** 人工模式在桌面端直接决定；辅助模式先由 LLM 提建议；自动模式将 LLM 评估交给本地暴露面策略校验。
4. ** 应用审批结果。** 允许后读取并交付密码；拒绝不返回密码；转人工则等待用户作出决定。
5. ** 留下可检查的记录。** 桌面端保留请求历史、审批理由和证据。AI 的详细审计标注在决定之后补充，不阻塞已经获批的读取。

| 模式                        | 谁来审查？                           | 谁作最终决定？                                            |
| --------------------------- | ------------------------------------ | --------------------------------------------------------- |
| **人工审批 / Human Review** | 人在桌面 UI 检查请求和证据。         | 人工批准或拒绝，无需配置模型。                            |
| **辅助审批 / Assisted**     | LLM 调查上下文并提供建议。           | 人在桌面 UI 作最终决定。                                  |
| **自动审批 / Auto**         | LLM 对照已保存的暴露面配置评估证据。 | Plankton 验证模型输出并执行本地策略：允许、拒绝或转人工。 |

发起读取的 Agent 与负责审批的 LLM 是**两个不同角色**。AI 审查期间，人仍可处理待定请求；之后返回的模型结果不能覆盖已经完成的人工决定。图中展示的是 **Protected（受保护）** 密码流程；被显式设为 **Direct（直接访问）** 的字段会跳过人工与 LLM 审批，但仍记录访问请求。

### 人设范围，LLM 按范围审查

每个密码的暴露面配置回答五个具体问题。集合保存默认配置，字段可以继承，也可以由人设置单独规则。Agent 可以在导入草稿里提出配置建议，人确认保存前可继续修改。

| 暴露面         | 人工设置什么？                         | 一个 API Token 的配置示例  |
| -------------- | -------------------------------------- | -------------------------- |
| **LLM 上下文** | 密码能否进入模型可见的上下文。         | 不进入提示词和聊天内容。   |
| **网络传输**   | 密码能否离开本机，以及允许发送到哪里。 | 仅允许 `api.example.com`。 |
| **本地持久化** | 密码能否写入本地存储。                 | 不写文件、不存缓存。       |
| **终端与日志** | 密码能否出现在输出或日志中。           | 不回显、不记录。           |
| **进程传播**   | 密码能否交给其他本地进程。             | 仅交给声明的使用程序。     |

上面是**示例配置**，不是默认值：受保护密码默认禁止网络暴露。LLM 需要报告实际暴露情况及其证据，本地代码再检查暴露等级、不确定性和目标地址。证据未知时不能自动放行；用途超出范围时，按策略拒绝或转人工。模型给出的低风险分数不等于批准依据。

## 信任与数据边界

Plankton 面向**可信本地计算机**上的密码访问审批。调用链是判断依据，不能替代沙箱，也不能证明进程获得密码之后的所有行为。

- **获批输出仍是敏感值。** 成功的 `plankton get` 会输出原始密码。Skill 要求直接交给不会回显或记录密码的程序；在模型可见的终端中单独运行 `get` 会泄露该值。
- **审批证据可能包含敏感上下文。** 当前实现保留未经脱敏的命令参数、传入的环境值、元数据和源码证据。不要把密码放进这些字段。正常审批载荷不会为模型解析出本次申请的保险库密码值。
- **审批 LLM 属于受信任工具。** 审批 Agent 能以较宽权限读文件和执行命令，应据此选择模型提供方与运行环境；本地优先不代表所有审批都离线完成。
- **本地校验约束自动放行。** 非法模型结果、关键证据缺失和策略越界不能静默转为自动批准。策略由人掌握，密码变更的最终确认也在桌面端完成。
- **保险库同步传输加密数据。** 同步内容是 KDBX 字节与非敏感版本／哈希元数据，不包含本地解锁文件；这项能力不等于远端 Server 审批或执行支持。

证据处理、工具权限、审批分流及审计的精确定义，见[自动审批契约](./automatic-approval.md)。
