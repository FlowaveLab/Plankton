# 审批契约核对：0.2.9

本次沿实际错误回查了批次与旧单请求两条路径，包括生成的 schema、反序列化、语义及证据校验、ACP 结果交付、重试、CLI 帮助和六份 secret-access Skill 文件。

| 发现 | 修正 |
| --- | --- |
| 请求 ID 批次仍复用旧 `batch_decisions` 字段；模型把空数组放进 `exposure_report` 后整批失败 | 为批次单独定义决策类型，从提示和 schema 删除旧字段；仅兼容已知位置的空数组。非空、null、未知字段和重复键仍报错 |
| schema 中 `exposure_report` 因 `serde(default)` 实际未列为必填，运行时却要求提供 | 单请求与批次 schema 均明确必填；引用的 surfaces/reason 增加非空约束。运行时继续检查五域、等级/状态、来源与行号 |
| 新批次绕过了旧 ACP 的同会话修正流程 | 共用有界修正流程：具体错误回给同一会话，最多一次，完整重验；保留原始输出、工具事件和两次尝试，共享原超时 |
| 引用缺失文件被分类成传输错误；文件引用与直接 JSON 的围栏处理不同 | 文件交付错误可以修正；两种交付共用完整围栏处理，文件引用采用严格类型解析，拒绝重复路径键 |
| 文档混用了必写 `result.json`、直接 JSON、旧共享报告和新逐请求报告 | 直接 JSON 为默认、文件引用为可选；明确旧单请求/接口的两阶段审核与新批次的同轮证据，不扩大凭据授权 |
| 中英文提示仍把声明脚本称为只读白名单，实际工具可自由读写 | 两种语言统一说明证据来源及不要执行消费者；保留工具能力，不引入专用 runner 或新配置 |
| 批次规则重复；Skill 重复说明启动、绑定、人工交接与边界，且把所有元数据变更都说成必须人工确认 | 去重并按任务路由；CLI 帮助与 Skill 区分配置允许的自动元数据确认和始终需人工确认的暴露策略编辑 |

有效的 deny/escalate、unknown 评估以及本地策略拒绝不触发格式修正。传输故障和取消不作为模型输出错误重试。旧分阶段路径已有的首次超时恢复仍要求确认会话清理，不叠加已耗尽的 schema 修正。

两次后仍有错误时：JSON 或请求 ID 覆盖错误使批次失败；结构及覆盖有效而某一条语义/证据错误时，仅该条转人工，其他条独立落库。人工决定优先，不重放消费者，也不修改已经人工处理的历史请求。

## 验证范围

- 回放本次真实失败的两条原始结果：离线严格解析、五域和引用校验，不调用模型、不执行消费者。原始材料仅保存在本机私有 `.artifacts/batch-field-regression`。
- 协议测试覆盖直接 JSON、文件结果、单请求、多请求、空旧字段、同会话修正、连续失败、单条失败隔离、缺失文件、空回复、传输错误及有效 unknown/deny。
- schema 回归检查必填报告、五域数组、禁用结果和旧字段移除；空兼容字段不得吞掉非空内容、未知字段或重复键。
- Skill 校验及 CLI 参数检查；`make check` 覆盖 Rust、前端、格式、类型和构建。
- 真实模型验收使用隔离 daemon 和虚构凭据，覆盖单凭据执行和同一消费者两项不同策略；结果保留在本机 `.artifacts/live-029-acceptance`。模型非确定性仍可能产生无法修正的结果，最终严格校验及人工路径保留。

## 本次结果

`make check` 全部通过：530 项 Rust 测试、402 项前端测试，以及格式、Clippy、类型和构建检查；私有原始失败样本另行回放通过。13 种协议场景验证最多一次同会话修正、失败隔离和不重试有效拒绝/unknown。

真实 DeepSeek / Pi 验收使用 2 个模型回合完成 3 条凭据评估，均无格式修正、无审核错误，引用详情完整。单凭据约 21.2 秒获批并执行；双凭据约 27.7 秒分别获批和按策略拒绝，消费者未执行。这是本次样本耗时，不是延迟保证。

Skill 六份文档从 3,344 减至 2,807 个空白分隔词（约 16%），删除重复说明并修正文义，保留执行能力和边界。此统计不是模型 token 或账单降幅。
